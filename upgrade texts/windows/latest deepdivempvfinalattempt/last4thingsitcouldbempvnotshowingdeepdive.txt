# DYLANDOS IPTV ULTIMATE — Black Screen Debug Master Guide
### "Video Is Playing But Hidden" — All Root Causes & Every Fix

---

## 🔴 UNDERSTAND THE EXACT PROBLEM FIRST

You said:
> Audio plays, stream details show it's active, but screen is **black**

This tells us with certainty:
- ✅ MPV process is alive and decoding
- ✅ The backing window exists
- ✅ The stream URL is valid
- ❌ **The visual pathway between MPV → backing window → transparent main window → your eyes is broken**

There are exactly **3 layers** that can cause this and only this symptom. Every fix below targets one of them.

```
┌─────────────────────────────────────────────┐
│  LAYER 3: React Main Window (transparent)   │  ← Could be opaque/black
│  [ OSD controls, menus, overlays ]          │
├─────────────────────────────────────────────┤
│  LAYER 2: MPV Backing Window (opaque black) │  ← MPV renders here
│  [ Actual video frames drawn by MPV/D3D11 ] │
├─────────────────────────────────────────────┤
│  LAYER 1: Desktop / Windows compositor      │
└─────────────────────────────────────────────┘
```

**The bug:** Somewhere in Layer 3, the "hole" that should show Layer 2 through is filled in with black.

## Fix 2C — The `show`/`hide` Video Window Logic Race Condition

This is a very common cause of "was working then broke after a few instances."

**File: `electron/main.cjs`** — look at your `mpv:show-video-window` and `mpv:hide-video-window` handlers:

```javascript
// electron/main.cjs

// ❌ BROKEN PATTERN — hide sets position off-screen, 
//    then show tries to restore but gets race condition:
ipcMain.handle('mpv:hide-video-window', () => {
  if (mpvVideoWindow) {
    mpvVideoWindow.setPosition(-10000, -10000); // ← Race condition prone
  }
});

ipcMain.handle('mpv:show-video-window', () => {
  if (mpvVideoWindow && mainWindow) {
    const bounds = mainWindow.getBounds();
    mpvVideoWindow.setPosition(bounds.x, bounds.y); // ← May restore to wrong position
  }
});
```

```javascript
// ✅ CORRECT PATTERN — use opacity and a proper hide state flag:

let mpvWindowShouldBeVisible = false;

ipcMain.handle('mpv:hide-video-window', () => {
  mpvWindowShouldBeVisible = false;
  if (mpvVideoWindow && !mpvVideoWindow.isDestroyed()) {
    // Move behind everything rather than off-screen:
    mpvVideoWindow.setAlwaysOnTop(false);
    // Keep the window in position but hide it behind main:
    if (mainWindow && !mainWindow.isDestroyed()) {
      mainWindow.setAlwaysOnTop(true);
      mainWindow.setAlwaysOnTop(false);
    }
    // Optional: minimize opacity by moving it fully behind
    // Don't move position — that causes layout glitches
  }
});

ipcMain.handle('mpv:show-video-window', () => {
  mpvWindowShouldBeVisible = true;
  if (mpvVideoWindow && !mpvVideoWindow.isDestroyed() && 
      mainWindow && !mainWindow.isDestroyed()) {
    // Ensure correct z-order:
    syncMpvWindowBounds();
    mpvVideoWindow.showInactive();
    // Bring main window back to front (with OSD on top):
    mainWindow.focus();
  }
});

function syncMpvWindowBounds() {
  if (!mpvVideoWindow || mpvVideoWindow.isDestroyed()) return;
  if (!mainWindow || mainWindow.isDestroyed()) return;
  
  const bounds = mainWindow.getBounds();
  mpvVideoWindow.setBounds(bounds);
  
  // Z-order: MPV backing window must be BELOW main window
  // setAlwaysOnTop with level ensures this on Windows:
  mpvVideoWindow.setAlwaysOnTop(false);
  mainWindow.focus(); // Brings main to top of Z-stack
}
```

## Fix 2D — Z-Order After Alt-Tab / Focus Loss

**File: `electron/main.cjs`**

The focus handler you mentioned in section 4.4 — this is where transparency breaks most often:

```javascript
// electron/main.cjs — replace your existing focus handler

mainWindow.on('focus', () => {
  // When window regains focus, the Windows compositor may have 
  // re-ordered the Z stack. Fix it:
  if (mpvWindowShouldBeVisible && mpvVideoWindow && !mpvVideoWindow.isDestroyed()) {
    // Step 1: Assert MPV window is NOT always-on-top
    mpvVideoWindow.setAlwaysOnTop(false);
    
    // Step 2: Briefly make main window always-on-top to force Z reassertion
    mainWindow.setAlwaysOnTop(true);
    
    // Step 3: Release always-on-top so other windows can go above it normally
    // Use a small delay — Windows DWM needs one frame to process the Z change
    setTimeout(() => {
      if (mainWindow && !mainWindow.isDestroyed()) {
        mainWindow.setAlwaysOnTop(false);
      }
    }, 50);
  }
});

mainWindow.on('blur', () => {
  // When losing focus, don't change Z order.
  // The MPV window should stay where it is.
  // Moving it on blur causes the "came back and now it's wrong" bug.
});

// Also fix this on restore from minimize:
mainWindow.on('restore', () => {
  if (mpvVideoWindow && !mpvVideoWindow.isDestroyed()) {
    mpvVideoWindow.showInactive();
    syncMpvWindowBounds();
    setTimeout(() => {
      if (mpvVideoWindow && !mpvVideoWindow.isDestroyed()) {
        mpvVideoWindow.showInactive();
      }
      if (mainWindow && !mainWindow.isDestroyed()) {
        mainWindow.focus();
      }
    }, 100);
  }
});
```

```javascript
    mpvWin.setBounds(b);

  parentWindow.on('resize', syncBounds);
```

## Fix 3B — The HWND Conversion Is Critical

**File: `electron/main.cjs`**

The HWND you pass to MPV via `--wid` must be a specific format. Wrong format = MPV spawns but renders to nowhere:

```javascript
// electron/main.cjs

// When getting HWND from the backing window:
const rawHandle = mpvVideoWindow.getNativeWindowHandle();

// rawHandle is a Buffer of the native HWND bytes

// CORRECT conversion for Windows x64:
// The HWND is stored as a 64-bit integer in the Buffer
// MPV on Windows expects it as a decimal string
let hwndDecimal;

if (process.platform === 'win32') {
  // Method 1 — Read as 32-bit LE (works for most Windows HWNDs which fit in 32 bits):
  hwndDecimal = rawHandle.readUInt32LE(0).toString();
  
  // Method 2 — If Method 1 gives wrong result (large HWND on some systems):
  // const low = rawHandle.readUInt32LE(0);
  // const high = rawHandle.readUInt32LE(4);
  // hwndDecimal = (BigInt(high) * BigInt(0x100000000) + BigInt(low)).toString();
  
  console.log(`[Main] Raw HWND buffer: ${rawHandle.toString('hex')}`);
  console.log(`[Main] Decimal HWND for MPV: ${hwndDecimal}`);
}

// Pass to MPV manager:
await mpvManager.initialize(mainWindow, settings, hwndDecimal);
```

## Fix 3C — node-mpv v1 WID Initialization Timing

Since your manifest confirms you use `node-mpv` v1, which **spawns MPV immediately in the constructor**, there's a race condition where MPV gets `--wid` before the backing window's surface is fully mapped by Windows DWM:

```javascript
// electron/mpvManager.cjs

async function initialize(mainWin, settings, hwnd) {
  console.log(`[MPVManager] Initializing with HWND: ${hwnd}`);
  
  // Your manifest says you wait 800ms after construction for DWM mapping.
  // This may not be enough. Try increasing to 1200ms:
  
  const NodeMPV = require('node-mpv');
  
  const mpvArgs = [
    `--wid=${hwnd}`,
    '--idle=yes',
    '--keep-open=yes',
    '--vo=gpu-next',
    '--gpu-api=d3d11',
    '--hwdec=auto-safe',
    '--no-border',
    '--no-osc',
    '--no-osd-bar',
    '--no-terminal',      // Reduce noise, node-mpv handles comms
  ];
  
  // node-mpv v1 constructor options:
  const mpvOptions = {
    socket: '\\\\.\\pipe\\dylandos-mpv-ipc',
    verbose: false,
    debug: false,
    binary: getMpvBinaryPath(),    // Your existing binary resolver
    additionalArguments: mpvArgs,
  };
  
  // Spawn node-mpv:
  mpv = new NodeMPV(mpvOptions);
  
  // ─── CRITICAL: Wait for DWM surface ─────────────────────────────
  // 800ms was your original wait. Test 1200ms if still black:
  await new Promise(resolve => setTimeout(resolve, 1200));
  // ────────────────────────────────────────────────────────────────
  
  // Then verify the WID was accepted by getting video dimensions:
  try {
```

## Fix 4A — The Show/Hide MPV Window React Side

**File: `src/components/MpvPlayer.tsx`**

The most common cause of "worked, then black" is this: MPV show/hide IPC calls happening at wrong times or being called redundantly:

```tsx
// src/components/MpvPlayer.tsx

export function MpvPlayer({ stream, streamType, onClose }: MpvPlayerProps) {
  const mpv = useMpv();
  
  // ── SHOW/HIDE MPV WINDOW ────────────────────────────────────────────
  // Show MPV backing window when component mounts:
  useEffect(() => {
    console.log('[MpvPlayer] Mounted — showing MPV video window');
    window.electronAPI.invoke('mpv:show-video-window')
      .catch(err => console.error('[MpvPlayer] Failed to show video window:', err));
    
    // Hide MPV backing window on unmount:
    return () => {
      console.log('[MpvPlayer] Unmounting — hiding MPV video window');
      window.electronAPI.invoke('mpv:hide-video-window')
        .catch(err => console.error('[MpvPlayer] Failed to hide video window:', err));
      
      // Also stop playback on unmount:
      window.electronAPI.invoke('mpv:stop')
        .catch(() => {});
    };
  }, []); // ← Empty dep array — only run once on mount/unmount
  
  // ── DO NOT call show-video-window inside the stream load effect ────
  // ── Having it in TWO places causes a hide→show race condition ──────
  
  // Load the stream:
  useEffect(() => {
    if (!stream?.url) return;
    
    if (streamType === 'live') {
      window.electronAPI.invoke('mpv:load-live', { 
        url: stream.url, 
        settings: getMpvSettings() 
      });
    } else {
      window.electronAPI.invoke('mpv:load-vod', {
        url: stream.url,
        startPosition: stream.resumePosition ?? 0,
        settings: getMpvSettings()
      });
    }
  }, [stream?.url, streamType]);
  
  return (
    <div
      className="relative w-full h-full"
      style={{ backgroundColor: 'transparent', background: 'transparent' }}
    >
      {/* Only render overlays — never the video itself */}
      {/* The video is in the backing window behind this */}
      
      {mpv.state.status === 'loading' && <LoadingOverlay />}
      {mpv.state.status === 'error' && <ErrorOverlay error={mpv.state.error} />}
      
      <PlayerControls mpv={mpv} streamType={streamType} onClose={onClose} />
    </div>
  );
}
```

## Fix 4C — Detect and Auto-Fix Black Screen at Runtime

Add a runtime transparency checker that fires when the player opens:

```tsx
// src/hooks/useTransparencyCheck.ts

export function useTransparencyCheck(isPlayerActive: boolean) {
  useEffect(() => {
    if (!isPlayerActive) return;
    
    // Small delay to let React render:
    const timer = setTimeout(() => {
      checkAndFixTransparency();
    }, 500);
    
    return () => clearTimeout(timer);
  }, [isPlayerActive]);
}

function checkAndFixTransparency() {
  // Check if html/body have been given a background:
  const htmlBg = getComputedStyle(document.documentElement).backgroundColor;
  const bodyBg = getComputedStyle(document.body).backgroundColor;
  
  const isOpaque = (color: string) => 
    color !== 'transparent' && 
    color !== 'rgba(0, 0, 0, 0)' &&
    !color.startsWith('rgba(0, 0, 0, 0');
  
  if (isOpaque(htmlBg)) {
    console.warn('[TransparencyCheck] html has opaque background:', htmlBg, '— fixing');
    document.documentElement.style.backgroundColor = 'transparent';
  }
  
  if (isOpaque(bodyBg)) {
    console.warn('[TransparencyCheck] body has opaque background:', bodyBg, '— fixing');
    document.body.style.backgroundColor = 'transparent';
  }
  
  // Force Electron to repaint the window with correct transparency:
  // This sends a signal to the main process to re-assert transparency:
  if (window.electronAPI) {
    window.electronAPI.invoke('window:force-repaint').catch(() => {});
  }
}
```

```javascript
// electron/main.cjs — add the handler:

ipcMain.handle('window:force-repaint', () => {
  if (!mainWindow || mainWindow.isDestroyed()) return;
  
  // Force a transparent repaint:
  const currentBounds = mainWindow.getBounds();
  
  // Method: briefly resize by 1px and back — forces compositor repaint:
  mainWindow.setBounds({ 
    ...currentBounds, 
    width: currentBounds.width + 1 
  });
  
  setTimeout(() => {
    if (mainWindow && !mainWindow.isDestroyed()) {
      mainWindow.setBounds(currentBounds);
    }
  }, 16); // One frame at 60fps
  
  // Re-assert background color:
  mainWindow.setBackgroundColor('#00000000');
});
```
